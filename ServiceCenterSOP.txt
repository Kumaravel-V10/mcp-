# Airline Call Center Business Processes

## Sample Processes for Common Agent-Assisted Service Requests

These processes are designed for a **customer service / contact center environment** where the agent handles servicing requests such as **name correction, ancillary sales, payment collection, schedule changes, refunds, and special service requests**.

***

# 1) Name Change / Name Correction Process

### Example: Asking for government-issued ID proof for name correction

## Business Objective

Ensure the passenger name in the booking matches the travel document, while complying with airline fare rules, security requirements, and fraud prevention controls.

## Trigger

Customer contacts the call center requesting:

* Name correction
* Spelling correction
* Title update
* Legal name change
* First name / last name inversion correction

## Process Flow

### Step 1: Validate customer details

Agent verifies:

* Booking reference / PNR
* Passenger full name
* Contact email / phone
* Security questions as per airline policy

### Step 2: Identify request type

Agent classifies the request into one of the below:

* **Minor correction** – typo within permitted character limit
* **Major correction** – substantial name change needing approval
* **Legal name change** – due to marriage/divorce/legal update
* **Passenger replacement** – usually not permitted; treated separately

### Step 3: Check airline policy and fare rules

Agent validates:

* Whether name correction is allowed
* Whether the request is within the permitted timeframe before departure
* Whether the route or airline partner restricts name changes
* Whether a fee applies
* Whether a valid named document is attached in the email for name validation
* Allow name change only if the name in the document matches the name change that is asked in the email

### Step 4: Request supporting document

If policy requires proof, agent asks customer to submit:

* Passport
* National ID
* Driving license
* Marriage certificate / legal affidavit (for legal change)
* Existing ticket and correct spelling evidence

### Step 5: Validate document received

Agent checks:

* Name on document
* Date of birth (if applicable)
* Consistency with booking details
* Whether change is correction vs. different traveler attempt

### Step 6: Check fee applicability

Agent verifies:

* Name correction fee
* Fare difference, if any
* Service charge / call center fee
* Taxes or reissue charges, if applicable

### Step 7: Trigger payment link (if fee applies)

If payment is required:

* Generate secure payment request
* Send payment link through approved channel (SMS/email/app)
* Inform validity time of the link
* Place booking on hold / queue until payment confirmation if policy allows

### Step 8: Update booking after payment / approval

Once payment and/or approval is complete:

* Correct name in reservation
* Reissue ticket if required
* Update SSR/OSI notes
* Add servicing remark / audit note
* Send updated itinerary or confirmation email

### Step 9: Close the case

Agent confirms:

* Corrected passenger name
* Charges collected
* Updated document sent
* Any further action required before travel

## Exception Handling

* **No valid proof provided** → advise cannot process request
* **Departure too close** → escalate to airport/helpdesk/urgent servicing queue
* **Partner/Interline booking** → refer to host carrier policy
* **Name change not allowed by fare rule** → explain limitations and alternatives

## Suggested Agent Script

> “To process the name correction, I’ll need a valid government-issued ID or supporting document showing the correct name. Once I verify the details, I’ll check whether any service fee applies and, if needed, I can send you a secure payment link.”

# 2) Paid Service Check and Payment Link Trigger Process

### Example: Checking for paid services and collecting payment from customer

## Business Objective

Enable agents to identify chargeable services and collect payment securely without manual cash handling.

## Trigger

Customer requests:

* Extra baggage
* Seat selection
* Meal upgrade
* Priority boarding
* Lounge access
* Date change / ticket reissue
* Name correction fee
* Penalty / service fee

## Process Flow

### Step 1: Verify booking/customer

Agent verifies booking ownership and customer identity.

### Step 2: Identify requested service

Agent determines what the customer wants:

* Ancillary purchase
* Post-booking change
* Waiver check
* Special handling request

### Step 3: Check eligibility

Agent checks:

* Booking status confirmed/open for servicing
* Flight not departed
* Service available on route/carrier
* Customer not already entitled through fare bundle, status, or disruption policy

### Step 4: Price the service

System/agent retrieves:

* Service fee
* Tax applicability
* Currency
* Fare difference (if reissue/change)
* Agent service fee if applicable

### Step 5: Explain charges and obtain acceptance

Agent informs customer:

* Total amount
* Service description
* Refundability conditions
* Payment time limit

### Step 6: Trigger payment link

Agent:

* Generates secure payment link through payment gateway
* Sends link to registered email/mobile
* Confirms delivery with customer
* Advises not to share OTP/payment details with anyone

### Step 7: Monitor payment status

Agent/system checks:

* Pending
* Paid
* Failed
* Expired

### Step 8: Fulfill service after successful payment

Based on service type, the agent:

* Adds baggage
* Assigns seat
* Reissues ticket
* Confirms paid meal
* Updates booking remarks
* Sends receipt/EMD/confirmation

### Step 9: Follow-up if payment fails

If payment fails:

* Resend link once if allowed
* Offer alternate approved payment method
* Cancel pending service request after SLA timeout

## Exception Handling

* **Price changed before payment completion** → requote before processing
* **Payment success but service not updated** → create back-office queue/case
* **Partial payment / gateway timeout** → verify with payment team before reprocessing
* **High fraud risk** → stop and escalate as per fraud SOP

## Suggested Agent Script

> “The requested service is chargeable. The total cost is \[amount]. If you’d like, I can send a secure payment link right away to your registered email or mobile, and once payment is successful, I’ll complete the service for you.”

# 3) Schedule Change / Flight Disruption Servicing Process

## Business Objective

Assist customers affected by airline-initiated changes and provide rebooking, refund, or travel alternatives.

## Trigger

* Flight cancellation
* Significant time change
* Misconnection due to schedule disruption
* Aircraft downgrade / service disruption

## Process Flow

1. Verify booking and impacted itinerary
2. Confirm disruption reason and eligibility
3. Check protected options / alternate flights
4. Offer options:
   * Accept new schedule
   * Rebook
   * Refund
   * Travel voucher (if policy permits)
5. Capture customer choice
6. Rebook/refund as per authorization
7. Update booking remarks and customer notification
8. Close case with documented disposition

## Key Controls

* Waiver code validation
* No collection where waiver applies
* Escalate if protected inventory not available

# 4) Refund Request Process

## Business Objective

Assess whether the ticket/service is refundable and initiate correct refund workflow.

## Trigger

Customer requests refund due to:

* Voluntary cancellation
* Medical issue (copassenger demise)
* Duplicate booking
* Schedule disruption
* Unused ancillary service

## Process Flow

1. Verify customer and booking
2. Identify refund reason
3. Check fare conditions and refund policy
4. Validate supporting documents if exception request:
   * Medical certificate
   * Death certificate
5. Calculate refund / penalty / non-refundable amount
6. Explain processing timeline
7. Create refund case / submit workflow
8. Send acknowledgment and reference number
9. Track completion and closure

# 8) Document Verification Process for Sensitive Changes

## Business Objective

Prevent fraud and ensure legal/security compliance for sensitive booking modifications.

## Trigger

Sensitive request such as:

* Name change
* DOB correction
* Gender update
* Passenger identity mismatch
* Refund to original form of payment exception
* Travel document correction

## Process Flow

1. Verify customer
2. Request approved proof documents
3. Validate document type and clarity
4. Compare with booking and customer statement
5. Flag suspicious cases
6. Approve / reject / escalate
7. Record document reference and audit notes
8. Process service if approved

# 9) Payment Failure / Retry Process

## Business Objective

Provide controlled handling when payment link fails or expires.

## Trigger

* Customer did not receive link
* Payment failed
* Payment timed out
* Payment completed but status not reflected

## Process Flow

1. Confirm contact details
2. Check payment gateway status
3. Reissue payment link if permitted
4. Reconfirm amount before retry
5. Wait for successful confirmation
6. Fulfill service only after confirmed payment
7. Escalate reconciliation issues to finance/payment team

# 10) Escalation Process for Non-Standard Requests

## Business Objective

Ensure requests outside standard policy are routed correctly.

## Trigger

* Waiver request
* Compassionate exception
* Medical case
* Fraud concern
* VIP/service recovery case

## Process Flow

1. Capture full case summary
2. Attach supporting documents
3. Tag reason code
4. Route to back-office / supervisor / fare desk
5. Inform customer of turnaround time
6. Monitor pending status
7. Action outcome and close case

# Key Business Rules to Include in the Process Design

## For Name Correction

* Minor typo may be free or low cost depending on policy
* Major name change should require document proof and/or approval
* Full passenger replacement should usually be blocked
* No changes after check-in/close to departure unless exception path exists

## For Paid Services

* Services should only be fulfilled after successful payment confirmation
* Price shown must be valid only for a defined period
* Payment link must be sent only to verified contact channels
* Refundability of ancillary should be clearly disclosed

## For Sensitive Requests

* Supporting documents must be mandatory where policy requires
* All actions should be logged for audit
* Fraud indicators should trigger supervisor review

# Best Practice Controls for Airline Call Centers

## Operational Controls

* Mandatory customer authentication before servicing
* Mandatory fare/policy check before commitment
* Standardized disposition codes
* Audit remark for every manual change
* Clear escalation path for exceptions

## Payment Controls

* Secure payment link only; agent should not collect card details manually unless approved process exists
* Payment success confirmation must come from system, not customer statement alone
* Auto-expiry for unpaid requests

## Compliance Controls

* Limit access to personal data
* Store only required service documents
* Mask sensitive information in notes/logs
* Record who performed the change and when
